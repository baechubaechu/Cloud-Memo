## 노트 템플릿 (2026-10-08 추가)

목표: 미리 지정한 문서 양식으로 새 노트를 즉시 만든다. 예: 회의록 폴더에서
새 노트를 만들면 회의록 양식이 나오고, 지정 단축키로 일지 양식의 노트를 만든다.

- [ ] **템플릿 관리** — 이름·기본 제목·Markdown 본문을 등록, 수정, 삭제.
  생성한 노트는 템플릿의 독립적인 사본이며, 템플릿을 나중에 바꿔도 기존 노트는 바뀌지 않는다.
- [ ] **폴더별 기본 템플릿** — 폴더에 템플릿을 지정하고, 그 폴더를 대상으로 하는
  새 노트 생성에 자동 적용. 지정하지 않은 폴더는 현재처럼 빈 노트 생성.
  하위 폴더 상속 여부는 구현 시 결정.
- [ ] **단축키로 생성** — 추가 단축키에 템플릿과 대상 폴더를 연결.
  입력 한 번으로 해당 폴더에 노트를 생성하고 바로 열어 편집. 명령 팔레트와 동일한
  생성 명령을 사용하며, 폴더 기본 템플릿보다 명시적으로 고른 템플릿을 우선한다.
- [ ] **설정 보관·일관성** — 템플릿과 폴더 연결을 사용자 서버에 저장.
  오프라인 사용 시 기기 보관 선택·암호화 원칙과 오프라인 생성 작업 큐를 따른다.
- [ ] **검증** — 폴더별 자동 적용, 지정 단축키·명령 팔레트 생성, 템플릿 없는 폴더,
  기존 문서 독립성, 삭제된 템플릿 연결 처리, 기본 단축키 충돌·IME 조합 중 실행 방지.

권장 순서: 템플릿 관리 → 폴더별 적용 → 사용자 지정 단축키 연결.
날짜·시간 같은 자동 치환 변수와 기존 노트에 템플릿 삽입은 후속 확장으로 검토한다.

## 단축키 (기본 + 사용자 지정)

**기본 단축키**는 앱·에디터에 내장하고 **수정 불가**(또는 OS 표준과 동일하게
고정). **추가 단축키**만 사용자가 조합을 지정해 **앱 명령**에 연결한다.
(옵시디언 Hotkeys / VS Code keybindings 와 유사.)

### 기본으로 포함 (고정·문서화)

- [x] **에디터** — `editorKeymaps.ts` 등: `Ctrl+Z` / `Ctrl+Y` undo·redo, 화살표·
  삭제, 인용 블록 Enter 등 CodeMirror keymap.
- [x] **앱** — `Ctrl+K` / `Ctrl+P` 명령 팔레트, 슬래시 메뉴 `↑↓`·Enter·Esc
  (`workbenchCommands.ts` / `CommandPalette.tsx`).
- [ ] **단축키 도움말**에 위 기본 목록을 **읽기 전용**으로 전부 노출(아래 보내기 절).

기본 키는 **사용자가 덮어쓰지 못함** — `Ctrl+Z` 가 다른 동작으로 바뀌면
회귀·지원 부담이 큼.

### 사용자 지정 단축키 (백로그)

- [ ] **설정 UI**
  - 설정(또는 `?` 도움말)에서 “단축키” 탭: 조합 기록(예: `Shift+Enter`) → 동작 선택.
  - 충돌 시 경고(이미 쓰는 조합·브라우저 예약 키).
- [ ] **연결 가능한 동작 (1차)**
  - `workbenchCommands` / 명령 팔레트와 동일한 **command id** 목록에서 선택.
  - 예: 새 노트, 오늘 노트 열기, 검색 포커스, 그리기 모드 토글, 사이드바 접기,
    우측 패널(첨부/할 일/버전) 열기.
  - **템플릿으로 새 노트 만들기** — 템플릿과 대상 폴더를 지정한 생성 명령.
- [ ] **연결 가능한 동작 (2차 — 페이지/노트 이동)**
  - **특정 노트 열기** — 노트 id 또는 제목(고정) 지정. 예: `Shift+Enter` →
    “인박스” 노트, “프로젝트 A” 노트.
  - **특정 폴더** 트리에서 선택·펼침.
  - **URL/딥링크** — `memo://note/{id}` 와 동일한 내비게이션(위젯·앱과 공유).
- [ ] **적용 범위(scope)**
  - **전역** — 에디터 밖(사이드바·목록 포커스)에서도 동작.
  - **에디터 포커스 시** — 본문 CodeMirror 안에서만(예: `Shift+Enter` 가 줄바꿈과
    충돌하면 “에디터에서만” 또는 chord `Ctrl+Shift+Enter` 권장).
  - **제목 input 포커스 시** — 제목 필드 전용 바인딩(선택).
- [ ] **저장**
  - 계정별 서버 저장(`user_settings.keybindings`) + 로컬 캐시; 기기마다 다를 수
    있음을 UI에 표시.
- [ ] **구현 메모**
  - 전역: `document` capture 단계 리스너 + command 디스패치.
  - 에디터: CodeMirror `Prec.highest` keymap 으로 사용자 map 병합
    ([`ROADMAP_TECH.md`](./ROADMAP_TECH.md) `editorKeymaps.ts`).

## Obsidian 볼트 이식 (import)

Obsidian에서 쓰던 마크다운 볼트를 CloudMemo로 옮기는 기능. **export와 짝**이 되며,
온보딩·데이터 이전 수요를 담당한다. (웹 데스크톱에서 먼저 제공, 대용량은
백그라운드·진행률 UI 고려.)

### 범위 (1차 — MVP)

## 동기화 · 사용자 허브

**원칙:** 벤더 메모 SaaS·제3자 동기화 저장소(Dropbox, iCloud, S3 등) 없음.  
동기화는 **사용자 소유 허브**(집 저전력 기기, 본인 VPS/VM)와 기기 간 **앱 내장 싱크**로만
이루어진다. 배포 프로필: [`deploy/README.md`](../deploy/README.md).

### 프라이버시 — 기기에 무엇이 남는가 (2026-10-04 결정)

**원칙:** 노트는 사용자의 서버(VPS·허브)와 사용자가 고른 자기 기기에만 있다. 제3자 저장소에
올라가지 않는 것은 물론이고, **고르지 않은 기기에는 아무것도 남지 않아야** 한다.

- [x] **기기 보관은 기본 꺼짐** — 로그인 화면의 「이 기기에 노트 보관 (오프라인 사용)」 을
  켠 기기에서만 사본·초안을 저장한다. 꺼진 기기는 오프라인 편집이 안 되는 대신 흔적이 없다.
  앱이 뜰 때 예전에 남은 사본이 있으면 지운다.
- [x] **보관은 암호화** — AES-GCM 256, 키는 비밀번호에서 PBKDF2(60만 회)로 만들고
  메모리에만 둔다(`web/src/lib/offlineStore.ts`). 그래서 보관을 켠 기기는 페이지를 새로
  열 때마다 비밀번호로 잠금을 푼다. 브라우저 폴더를 통째로 가져가도 비밀번호 없이는 못 읽는다.
- [x] **로그아웃하면 전부 삭제** — 사본, 못 보낸 초안, 키 재료, 보관 설정.
- [x] **브라우저 캐시에 안 남김** — API 응답에 `Cache-Control: no-store`. 서비스 워커는
  `/api/*` 와 다른 출처 응답을 저장하지 않는다(`next.config.ts`, 기본 설정은 평문으로 저장했음).
- **첨부(이미지·오디오·파일)** — 기기에 저장하지 않는다. 볼 때마다 서버에서 받아 메모리에만
  두고 탭을 닫으면 사라진다. 그래서 오프라인에서는 안 보인다.
- 남은 것
  - [ ] 로그인 화면 말고 앱 안(설정)에서도 보관 켜기/끄기, 「지금 이 기기에서 지우기」.
  - [ ] 오프라인에서 서버 확인 없이 잠금 해제하는 경로 — 코드는 있으나 실제로 확인 못 함
    (앱 셸 오프라인 실행이 먼저 필요).
  - [ ] 암호화 강도 = 비밀번호 강도. 짧은 비밀번호면 사본도 약하다 — 안내 문구 또는 최소 길이.
  - [ ] 로그인 토큰은 여전히 `localStorage` 에 평문(14일). 보관을 끈 기기에서는 탭을 닫으면
    지워지는 `sessionStorage` 로 옮길지 검토.
  - [ ] 첨부를 오프라인에서 보려면 같은 보관소에 암호화해 저장(용량 한도·선택 보관).
  - [ ] HTTP 로 접속하면(LAN IP 개발 접속 등) 브라우저가 암호화 API 를 안 열어 보관이 꺼진다
    — 배포는 HTTPS 라 해당 없음. 안내만 뜬다.
  - [ ] 서버 쪽 저장(Postgres·`uploads/`)은 평문. 디스크 암호화는 배포 문서에서 안내.

### 동기화 방식 (2026-10-03 결정 · 1단계 구현)

요구: 여러 기기에서 고쳐도 **2~3초 안에 반영 + 자동 병합**. 글자 단위 실시간
공동 편집(CRDT)은 필요 없음. Obsidian Sync 와 같은 **노트 단위 버전 + 텍스트 병합**.

- [x] **노트별 revision + 서버 3-way 병합**
  - 저장할 때 클라이언트가 "마지막으로 서버와 맞췄던 revision·제목·본문" 을 같이 보낸다.
    서버 revision 과 다르면 `diff-match-patch` 로 병합하고(`services/sync.py`),
    병합 직전 상태를 버전 히스토리에 `before_merge` 로 남긴다.
  - 제목·폴더·태그·즐겨찾기는 마지막 수정이 이긴다.
- [x] **변경 폴링** — `GET /api/sync/changes?since=<seq>` 를 3초마다(탭이 보일 때만).
  전역 카운터 `sync_counter.seq`, 노트별 `change_seq`, 삭제는 `note_tombstones`.
- [x] **열린 노트에 반영** — 편집 중이 아니면 캐럿을 유지한 채 본문 교체(undo
  히스토리 제외). 편집 중이면 그대로 두고 다음 저장 때 서버가 병합.
- [ ] 그림 레이어 병합 — 지금은 마지막 저장이 이긴다. stroke id 기준 합집합 + 삭제 기록.
- [ ] 같은 줄을 양쪽에서 고치면 두 수정이 이어 붙는다(`line (laptop) (phone)`).
  Obsidian 과 같은 한계. 필요하면 「충돌 사본 만들기」 옵션.
- [ ] 폴링 → 푸시(SSE/WebSocket). 지금 간격으로 충분하면 보류.

    「오프라인 · 연결되면 저장」 이 되고 5초마다·`online` 이벤트에 재시도한다. 탭을
    닫았다 열어도 앱 시작 시 남은 초안을 올리고, 그 사이 다른 기기 수정과는 서버가 병합.
    노트가 지워졌으면 「(복구)」 노트로 살린다.
  - [x] **2단계 — 노트 사본 내려받기** *(2026-10-03)*: 모든 노트(아카이브 포함)의
    본문을 IndexedDB `notes` 에 내려받고, 폴링에서 바뀐 것만 다시 받는다(`cacheSeq`).
    폴더·태그 목록도 보관. 서버에 닿지 않으면 상단에 오프라인 띠가 뜨고, 목록·검색·
    노트 열기가 사본으로 동작한다. 오프라인에서 여러 노트를 오가며 고칠 수 있고,
    다시 연결되면 밀린 편집을 모두 올린다. **보관을 켠 기기에서만**, 암호화해서 저장한다
    (위 "프라이버시" 절). 로그아웃 시 전부 지운다.
  - **아직 구현 못 한 것**
    - [ ] **앱을 오프라인에서 새로 열기** — 서비스 워커로 앱 셸 캐시. `next-pwa` 가
      개발 모드에서 꺼져 있어 프로덕션 빌드에서만 확인 가능. 토큰 만료 시 처리도 필요.
    - [ ] **오프라인 작업 큐** — 새 노트 만들기, 삭제, 이름 변경(사이드바), 폴더·태그
      생성/이동/삭제, 즐겨찾기·아카이브. 지금은 오프라인에서 누르면 안내 문구만 뜬다.
      임시 id 로 로컬에 만들고 재연결 시 순서대로 보내는 큐가 필요.
    - [ ] **그림 레이어 오프라인 보관** — 오프라인에서 그린 stroke 는 노트를 바꾸면
      사라진다. 초안처럼 기기에 보관 + 서버 병합(stroke id 합집합).
    - [ ] **첨부 오프라인** — 본문 이미지·오디오는 오프라인에서 안 보인다(자리표시만).
      본 적 있는 첨부를 기기에 보관, 오프라인 업로드 대기열.
    - [ ] 오프라인에서 버전 히스토리·할 일 패널(지금은 비어 보임. 할 일은 사본에서 계산 가능).
    - [ ] 사본 용량 관리 — 노트가 아주 많을 때 전체 내려받기 진행 표시, 한도.
    - [ ] 자동 동기화 켜기/끄기와 연결(끄면 이 오프라인 경로만 쓰도록).
    - [ ] 네이티브·데스크톱 앱에서는 같은 구조를 SQLite/파일로 (저장소 인터페이스 교체).
  - **직접 확인 필요** — 자동 검증은 요청을 강제로 실패시켜 흉내 낸 것. 실제로

- [~] **충돌 처리**
  - 본문은 자동 병합(위). 병합 직전 상태는 버전 히스토리에서 복원 가능.
  - 남은 것: 병합이 일어났음을 알리는 표시, 「충돌 사본 만들기」 옵션.

## 홈 · 바탕화면 위젯 (Rainmeter 스타일)

**Rainmeter**처럼 바탕화면·홈 화면에 항상 떠 있거나 한 번에 보이는 **작은 패널**.
본 앱을 매번 열지 않고 오늘 노트 확인·즉시 메모·일정 훑기를 한다. 웹 브라우저가
아니라 **데스크톱 클라이언트(Windows/macOS) + 네이티브 앱(iOS/Android)** 에서
구현한다.

### 위젯 종류 (백로그)

- [ ] **오늘 노트**
  - `YYYY-MM-DD` 데일리 노트 제목·본문 일부(마크다운 plain 요약) 표시.
  - 탭/클릭 → 해당 노트를 앱·웹에서 열기(딥링크 `memo://note/{id}` 등).
  - §0 **데일리 노트**·[`ROADMAP_PLATFORM.md`](./ROADMAP_PLATFORM.md) 일정 절과 연동.
- [ ] **빠른 메모**
  - 한 줄~짧은 텍스트 입력 → 지정 폴더/인박스 노트에 append 또는 새 노트 생성.
  - 오프라인 큐 후 동기(앱·데스크톱 공통).
  - Windows: Rainmeter 스킨처럼 **항상 위** 작은 입력창 옵션.
- [ ] **캘린더**
  - 월/주 미니 뷰: 데일리 노트가 있는 날, `due:`·체크리스트 마감(있을 경우) 표시.
  - 날짜 탭 → 그날 데일리 노트 또는 노트 목록.
  - 풀 캘린더 UI는 플랫폼 로드맵 **일정 / 캘린더** 와 단계적으로 합침.

### 플랫폼별 (백로그)

- [ ] **Windows**
  - Rainmeter 유사: 투명·드래그 가능 데스크톱 오버레이, 다중 모니터, DPI.
  - Win11 **위젯 보드** 연동은 2차(스토어·API 제약 별도 조사).
- [ ] **macOS**
  - Notification Center / **WidgetKit** (오늘 노트·빠른 메모 위주).
- [ ] **iOS / Android**
  - 홈 스크린·(선택) 잠금 화면 위젯, 위젯 갱신 주기·배터리 정책.
- [ ] **공통**
  - 위젯 전용 **경량 API** 또는 캐시(토큰·오늘 노트 id·캘린더 요약 JSON).
  - 테마: 라이트/다크·투명도(데스크톱).

### 구현 순서 (권장)

1. 데일리 노트 API·딥링크 확정 → **오늘 노트** 위젯 1종.
2. **빠른 메모** (capture endpoint + 오프라인 큐).
3. **캘린더** 미니 뷰(플랫폼 일정 절과 스펙 공유).
4. Windows Rainmeter 스타일 오버레이 vs 모바일 홈 위젯을 플랫폼 팀이 병렬.

  - **Sticky = 특정 노트를 데스크톱에 고정**(빠른 메모 + 인박스 노트 핀).

  - 구글 캘린더 실시간 동기화, 우측 확장창에서 일·주·월 리스트·검색.

## UX 잔여 작업

- [x] **같은 폴더의 노트 이름 중복 방지** *(2026-10-08)* — 루트 포함, 같은 사용자·폴더
  안에서는 앞뒤 공백·영문 대소문자를 무시해 중복 생성·이름 변경·이동을 거절.
  제목 미지정 생성은 `무제 노트`, `무제 노트 2`, `무제 노트 3` 순으로 빈 이름을 배정.
  제목 입력칸에서 중복 이름을 쓰고 다른 곳을 클릭해 편집을 확정하면, 서버에서 사용 가능한
  무제 노트 이름으로 자동 변경하며 본문은 보존. 사이드바 이름 편집 확정에도 동일하게 적용.
  다른 폴더의 같은 제목은 허용. 동시 요청은 사용자 행 잠금으로 직렬화.
  버전 복원·AI 제목 변경·폴더 삭제에 따른 루트 이동에도 적용. 기존 중복 이름은 자동 변경하지 않음.
