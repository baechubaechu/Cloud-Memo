# 브라우저 직접 점검 (2026-10-08 수정 이후)

현재는 테스트 절차만 작성됨. 아래 항목을 통과한 것으로 처리하지 않는다.
결과는 실행 날짜·브라우저·증상과 함께 기록하고 `ROADMAP_TECH.md`에도 반영한다.

## 준비

- Docker Desktop을 켜고 레포 루트에서 실행:
  `powershell.exe -ExecutionPolicy Bypass -File .\scripts\dev-all.ps1`
- `http://localhost:3000`에서 테스트용 폴더와 노트 A·B를 만든다.
  삭제·로그아웃 시험은 테스트 데이터로 진행. 로그아웃하면 미전송 초안도 삭제된다.
- 동기화는 같은 계정의 별도 브라우저 창 두 개로 확인. 두 창을 나란히 띄워 두면
  숨겨진 탭에서 폴링이 쉬는 동작과 구분하기 쉽다.
- 로컬 앱은 Wi-Fi를 꺼도 localhost API에 연결된다. 오프라인 시험은 API 창에서
  Ctrl+C로 서버만 멈춘다. 프런트·DB는 유지. 재연결은 별도 터미널에서
  `powershell.exe -ExecutionPolicy Bypass -File .\scripts\dev-api.ps1` 실행.
- 개발 자동 로그인은 잠금을 자동 해제할 수 있다. 잠금 화면 시험은 자동 로그인을
  끈 환경에서 진행해야 확실하다. 서비스 워커 캐시 시험은 프로덕션 빌드에서만 가능.

## 추가 확인

- [ ] **노트 이름:** 같은 폴더에서 새 노트 3개를 만들면 `무제 노트`, `무제 노트 2`,
  `무제 노트 3`처럼 생성되는지(기존 이름이 있으면 다음 빈 번호 사용). 두 노트를 같은 제목으로
  바꾸고 다른 곳을 클릭하면 사용 가능한 `무제 노트` 이름으로 자동 변경되는지.
  본문이 유지되는지, 같은 이름이 있는 폴더로 이동은 거절되는지.
  다른 폴더에서는 같은 제목을 사용할 수 있는지.

- [ ] **버전 복원:** 내용 수정으로 자동 버전이 생긴 테스트 노트에서 버전 복원.
  본문이 즉시 바뀌고 새로고침 후에도 복원 상태가 남는지. 매 편집마다 새 버전이 생기지는 않는다.
- [ ] **잠금:** 자동 로그인 없이 보관을 켜고 로그인한 뒤 새로고침.
  비밀번호 입력이 필요하고, 틀린 비밀번호는 거절되는지.
- [ ] **오프라인 충돌·복구:** 다른 기기가 서버에 접근 가능한 환경에서 한 기기만
  네트워크 요청을 차단. 양쪽 수정 후 재연결 시 병합, 다른 기기에서 삭제한 노트의 초안은
  `(복구)` 노트로 살아나는지. 로컬 API 전체 정지만으로는 두 기기의 이 조건을 만들 수 없다.
- [ ] **기존 평문 캐시 정리:** 프로덕션 환경의 이전 설치에서 `apis`·`cross-origin`
  Cache Storage가 남아 있는지 확인 후 새 버전 실행. 두 캐시가 삭제되고 노트 열기 후에도
  다시 생성되지 않는지. 개발 모드의 자동 캐시 삭제만으로 통과 판정하지 않는다.

아직 구현하지 않은 것: 완전히 오프라인인 상태에서 앱을 새로 실행, 새 노트·폴더 생성과
삭제 대기열, 이미지·오디오 사본, 그림 레이어의 오프라인 보관. 이 기능들은 현재 통과 조건이 아니다.

DB 열기 실패·트랜잭션 취소·여러 탭 삭제 차단은 자동 회귀 테스트로 확인했다:
`node scripts/test_device_storage.cjs`. 실제 입력·두 창 동기화 점검은 별도로 필요하다.
